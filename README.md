# Електронний каталог відеоконтенту (YouTube Clone)

Fullstack-застосунок для зберігання, каталогізації та перегляду відеоконтенту: Single Page Application на React та REST API на нативному PHP з базою PostgreSQL. Розроблено як pet-проєкт для демонстрації навичок fullstack-розробки.

## Основний функціонал

- **Каталог відео:** список відео та миттєва фільтрація за категоріями на стороні клієнта
- **Пошук (`/search`):** за назвою відео, назвою каналу та категорією без урахування регістру (`ILIKE`)
- **Автентифікація:** реєстрація та вхід, stateless JWT (термін дії 24 години), паролі хешуються через bcrypt
- **Історія переглядів:** автоматично фіксується для авторизованих користувачів
- **Панель адміністратора:** створення, редагування та видалення відео. Доступ обмежено за роллю (RBAC): на клієнті через `ProtectedRoute`, на сервері через перевірку ролі в токені (403)

## Технологічний стек

**Frontend**
- React 19, TypeScript, Vite
- Tailwind CSS 4
- React Router 7
- Context API для стану авторизації (`AuthContext`)
- Власний хук `useApi`: обгортка над `fetch` з підстановкою токена та глобальною обробкою помилок

**Backend**
- PHP 8.2 (нативний, без фреймворків)
- PDO з підготовленими запитами
- JWT (HS256), підпис і перевірка реалізовані вручну через `hash_hmac` / `hash_equals`
- bcrypt для паролів

**База даних та інфраструктура**
- PostgreSQL 15
- Docker та Docker Compose

## Архітектура клієнта

- **`AuthContext`** тримає користувача і JWT, зберігає їх у `localStorage` і надає `login`, `register`, `logout`.
- **`useApi`** повертає функцію `request<T>(endpoint, options)`: додає заголовок `Authorization: Bearer ...`, ставить `Content-Type: application/json` для рядкових тіл, парсить JSON-відповідь і кидає `Error` з повідомленням бекенду, якщо відповідь не успішна. На статус 401 виконує вихід з акаунту й перенаправляє на `/login`. Функція мемоізована через `useCallback`, бо використовується в масивах залежностей `useEffect`.
- Вхід і реєстрація йдуть напряму через `fetch`, а не через `useApi`: для них 401 означає «невірні дані», а не «сесія закінчилась».
- **`ProtectedRoute`** захищає маршрути `/history` (авторизований користувач) та `/admin/*` (роль `admin`).

### Маршрути клієнта

| Шлях | Опис | Доступ |
| --- | --- | --- |
| `/` | Каталог із фільтром за категоріями | усі |
| `/watch/:id` | Перегляд відео | усі (історія пишеться для авторизованих) |
| `/search` | Пошук | усі |
| `/login`, `/register` | Вхід і реєстрація | усі |
| `/history` | Історія переглядів | авторизовані |
| `/admin`, `/admin/create`, `/admin/edit/:id` | Керування відео | `admin` |

## API

| Метод | Маршрут | Доступ | Опис |
| --- | --- | --- | --- |
| GET | `/` (`?q=`) | усі | Список відео, опційно пошук |
| POST | `/register` | усі | Реєстрація |
| POST | `/login` | усі | Вхід, повертає користувача й JWT |
| GET | `/history` | JWT | Історія переглядів користувача |
| POST | `/history` | JWT | Записати перегляд (`video_id`) |
| POST | `/` | `admin` | Створити відео |
| PUT | `/videos/:id` | `admin` | Оновити відео |
| DELETE | `/videos/:id` | `admin` | Видалити відео |

## Локальне розгортання (Docker)

Потрібні встановлені Docker та Docker Compose.

1. Клонування репозиторію:
   ```bash
   git clone https://github.com/WolandEmort/utube-pet-project.git
   cd utube-pet-project
   ```

2. Змінні оточення. Створіть файл `.env` у корені (приклад у `.env.example`):
   ```env
   DB_PASSWORD=your_secure_password
   JWT_SECRET_KEY=your_secret_key_for_jwt
   ```
   Створіть файл `frontend/.env`:
   ```env
   VITE_API_URL=http://localhost:8080
   ```
   (адреса має починатися з `http://`, інакше браузер сприйме її як відносний шлях)

3. Запуск:
   ```bash
   docker compose up -d --build
   ```

4. Доступ:
   - Frontend: http://localhost:5173
   - Backend API: http://localhost:8080
   - PostgreSQL: порт 5432

Роль користувача (`user` або `admin`) задається полем `role` у таблиці `users`.

### Перевірка коду frontend

```bash
cd frontend
npm run lint
npm run build   # tsc -b && vite build
```

## Структура бази даних

Три таблиці, ідентифікатори типу UUID:

- **users**: email, хеш пароля, ім'я, роль (`user` / `admin`)
- **videos**: метадані відео (назва, опис, канал, категорія, URL прев'ю, перегляди, дата публікації)
- **view_history**: зв'язок між `users` та `videos` для історії переглядів. Зовнішні ключі з `ON DELETE CASCADE` зберігають цілісність при видаленні користувача чи відео

## Безпека

- Запити до БД виконуються лише через підготовлені запити (PDO prepared statements)
- Паролі хешуються bcrypt (`password_hash` / `password_verify`)
- Підпис JWT (HMAC-SHA256) і термін дії перевіряються на кожному приватному маршруті; порівняння підпису через `hash_equals`

## Відомі обмеження

- JWT зберігається в `localStorage`, тому вразливий до XSS. Альтернатива: httpOnly cookie
- CORS на бекенді відкритий для всіх origin (`Access-Control-Allow-Origin: *`); для production варто обмежити до адреси фронтенду
- Бекенд запускається вбудованим сервером `php -S`, придатним лише для розробки
- Автоматичних тестів немає (ручні запити лежать у `backend/src/api_test.http`)
